Chart Analyzer Architecture

Chart Analyzer: архитектура

Пять контейнеров. API только принимает запрос и отдаёт прогресс; сам анализ выполняет воркер, а задача попадает к нему через outbox и RabbitMQ.

Путь одного анализа

  1. Клиент отправляет POST /analyses: картинка, язык, x-user-id, Idempotency-Key. API проверяет файл (настоящая картинка, формат, размер), ключ идемпотентности и квоту с резервом.
  2. Одной транзакцией в Postgres создаются анализ и строка outbox; файл уходит на диск. Клиент сразу получает 202 и id.
  3. Публикатор outbox читает неотправленные строки и публикует id анализа в очередь tasks.
  4. Воркер берёт задачу и атомарно переводит анализ в статус «в работе». Дубль сообщения пропускается.
  5. Распознавание в OpenAI: это график и виден ли тикер; если нет, клиент получает ошибку «Please upload a clear trading chart». Затем данные тикера из Finnhub через кэш, полный анализ в OpenAI. Результат каждого шага сразу сохраняется в Postgres.
  6. После каждого шага воркер пишет стадию в Redis. API отдаёт стадии и итог клиенту потоком; при обрыве клиент переподключается и получает их заново.

Что происходит при сбоях

СбойРеакция системы
Оборвалась сеть клиентаВоркер продолжает; клиент переподключается к потоку или забирает результат по GET
Клиент повторил POSTПо ключу идемпотентности возвращается тот же анализ
Упал API после записи в базуСтрока outbox осталась, задача всё равно будет опубликована
Упал воркер посреди анализаСообщение вернётся в очередь; новый воркер продолжит с сохранённого шага
Временный сбой OpenAI или FinnhubОчередь retry: пауза растёт с каждой попыткой
Попытки кончилисьСообщение в DLQ, анализ неуспешен и в квоту не идёт
